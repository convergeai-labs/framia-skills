# Framia 模型路由(实测矩阵 + 决策规则)

> 快照:2026-08 初实测。Framia 模型目录迭代快,**每次开工先看当前目录**,本表作为先验而非定论。

## 失败分类学(比模型名单更重要)

| 错误 | 性质 | 应对 |
|---|---|---|
| `biz_code: 5001` 内容审核拒绝 | **政策性**。真人/品牌/地标参考图触发,改 prompt 措辞无法绕过 | 只允许一次"虚构化"改写:去真实人名/队名/联盟名/地标/logo,室内-only,纯虚构主体。再失败即放弃该路由 |
| `biz_code: 5000` 运行时生成失败 | **暂时性**。服务侧问题 | 可原样重试 1 次(总重试 ≤2);换时间窗再试 |
| `timeout of 30000ms exceeded` / 队列长时间卡同一进度 | **平台坏时间窗** | 停止批量提交;等窗口或改走重剪已验证素材的兜底方案 |
| `Image generation does not support video references` | **模式误用** | 检查节点的输入类型与模型支持的参考模式 |

## 实测矩阵(真人参考图驱动运动视频)

| 模型 | 结果 | 结论 |
|---|---|---|
| Wan 2.7 `multi_reference` | ✅ 多条 5s/9:16/720p 全部成功,真人相似度+真运动 | **人物场景主力路由**。短板:720p,放大到 1080 发虚 |
| Seedance 2.0 | 接受 `multi_reference` 模式但运行时 5000 ×2;零参考也 30s timeout | 暂时性故障,值得每次开工 1 条探针,不过即弃 |
| Kling 3.0 Omni | 5001 | 真人参考政策性拒绝,不硬闯 |
| Veo 3.1 | 5001(直传参考图) | 同上 |
| GPT Image(身份锚定图) | 5001 | 同上 |

## 分层路由规则

1. **有人物、要相似度** → 已验证的参考驱动路由(Wan 2.7 `multi_reference` + 合规授权参考图)。
2. **无人物氛围场**(空镜、城市、道具特写)→ 零参考高分辨率模型(Veo / Seedance / Kling / 当期最强),不触发真人审核,还能补上参考路由的分辨率短板。
3. **新模型/新版本** → 只给 1–2 次探针预算:先跑一条最便宜场景,成功才纳入路由表,失败立刻锁回已验证路由,不恋战。
4. **同一主体的连续性** > 单镜画质。混用模型时优先保证同一主角全片形象一致;不同模型生成同一角色几乎必然形象断裂。

## 参考图合规

- 只用有授权的参考图(如 CC BY),来源与许可证记录在项目文档里;
- 不用混淆/遮掩身份的参考图,不写规避审核的 prompt——这是红线,不是技巧问题;
- 真人题材成片必须带虚构披露 overlay。

## 套餐与导出门禁(2026-08-12 实测,替代 08-03 旧结论)

- **套餐门禁与下载策略变化极快,每次开工以实测为准**:
  - 2026-08-03:Free 套餐所有下载/导出均付费墙,Kling 3.0 Free 可用;
  - 2026-08-12:Kling 3.0 已转 **Basic+ 专属**;而**节点级「下载视频/下载音频」在 Free 下可直接下载**(同一周内两个方向的结论都翻过面)。
- Free 可用视频模型(08-12 实测跑通,均支持 9:16):Seedance 2.0 Mini、HappyHorse 1.1、Wan 2.7;编辑器导出在 Free 下是否可行未验证(本次走节点下载+本地组装)。
- 各模型每秒 credit 单价以画布内实时目录为准;**实际扣费可能高于目录单价**(分辨率/时长系数),批量生成前先跑 1 条探针并对账。
- **任何套餐升级都必须先拿用户明确授权,Agent 不得自行操作**;升级提示出现时,正确动作是换 Free 可用路由继续,并把升级决策交还用户。
- Free 档队列可能长时间卡同一进度(实测 5min+ 不动):按"坏时间窗"处理,取消换模型;同 prompt 换模型可显著提速。
- **零参考双主体配色控制**:同 prompt 两条独立生成的片子保持了同一品红+青双车设计语言,适合系列镜头;验收只卡"两色清晰可辨",不卡色号。
- 编辑器导出前确认项目画幅:默认 16:9 会把 9:16 素材 pillarbox,先切 9:16 再导出。
